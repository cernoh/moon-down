THROWAWAY sketch for #10 TUI screens and keybindings (branch research/10-tui-sketch). Flip variants with ?variant=A|B|C, the bottom bar, or ←/→. Press ? for the proposed keybindings. Mock data follows the #7 verdict: one row per handle, worst-case header rollup, error text on children only.
Render/update loop (same under all variants — judge in Q4) key-event stream + 1s poll tick + completion-event fan-in → one mpsc channel → single event loop owns state → render-on-change only. Blocking work (extract per #11, account checks per #9) runs on spawn_blocking and posts back. Pattern: ratatui counter-async full-async Tui. Engine handle = GID or crate id (TBD by #13); "1s tick" is the poll interval, not a render timer.
Proposed keybindings (judge in Q2): j/k or ↑/↓ move · h/l or ←/→ collapse/expand · Enter details · 1..6 jump screen · Tab next screen a add dialog · space pause/resume (fan-out, per #7) · d remove (keep files) · D delete +files (confirm) r retry / re-add · e retry extract (#11 ExtractFailed) · ? this help · q quit · Esc close dialog
